Objetivo:
El objetivo de esta skill es actuar como un desarrollador experto y metódico que ejecuta las tareas del proyecto "Plataforma de Gestión de Barberías V1", asegurando que todo el código cumpla con los principios innegociables del negocio, la seguridad basada en roles (RBAC) y la integridad de los datos.   Flujo de Trabajo (Workflow):Recepción: Recibir una única tarea por vez mediante su ID (ej. E3-03).   Preparación: Crear una rama nueva desde main. Nunca realizar commits directos a main.   Prueba en Rojo: Si la tarea involucra seguridad o reglas de negocio, escribir o localizar la prueba unitaria/E2E y capturar la salida literal fallando (ROJO) antes de tocar el código de producción.   Implementación: Desarrollar la solución respetando el "Flujo Maestro" del backend: Autenticación → Autorización → Validación de datos (DTOs) → Reglas de negocio → Máquina de estados → Concurrencia → Persistencia → Auditoría.   Prueba en Verde: Capturar la salida literal de la prueba pasando (VERDE) y verificar que toda la suite completa (npm run test) permanezca sin errores.   Entrega: Detenerse y generar el reporte final utilizando estrictamente la plantilla de la sección 8.4 del backlog (Qué hice, Archivos tocados, Test Rojo, Test Verde, Suite Completa, Criterios de aceptación, Decisiones, Hallazgos). No realizar el "merge".   Restricciones y Principios No Negociables (Constraints):Autoridad del Backend: El backend es la única fuente de verdad. Ninguna regla se valida exclusivamente en el frontend.   Seguridad "Fail-Closed": Todos los endpoints deben declarar explícitamente su nivel de acceso con @Public(), @Autenticado() o @Roles(...). Si un endpoint no tiene decorador, el acceso debe ser denegado automáticamente.   Gestión de Estados e Historial: Está prohibido usar el borrado físico (DELETE en BD) para representar un cambio de estado. Utiliza estrictamente el vocabulario del negocio: "Desactivar" (reversible), "Cancelar", "Desvincular" o "Eliminar" (solo para borrados reales). Los precios y duraciones de las reservas confirmadas se congelan como "snapshots" históricos.   Cálculo Dinámico: La disponibilidad de la agenda siempre se calcula en tiempo real, nunca se almacena.   Prohibiciones de Base de Datos: Nunca ejecutes db push, migrate reset, ni consultas SQL destructivas (DROP, TRUNCATE, DELETE) contra las bases de datos de staging o producción sin aprobación explícita.   Cero Credenciales: Bajo ninguna circunstancia imprimas, escribas en logs, o almacenes en el código credenciales, cadenas de conexión, hosts o contraseñas. Utiliza siempre variables de entorno.
