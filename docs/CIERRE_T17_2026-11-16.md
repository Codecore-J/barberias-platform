# CIERRE T-17 · Categorías en solo lectura para el ADMINISTRADOR

**Fecha:** 2026-11-16 · **Rama:** `feat/t17-categorias-lectura-admin` · **Base:** `main` (`d24e452`)

## Qué pedía

El ADMINISTRADOR global debía poder **leer** las categorías de cualquier sede y **no poder escribir**, con
test de escritura en rojo **antes** de tocar el guard del frontend.

## Diagnóstico (estado previo, verificado)

| Capa | Comportamiento antes |
|---|---|
| `RolesGuard` | El ADMINISTRADOR pasaba por jerarquía en **todas** las rutas, lectura y escritura. |
| `OperadorBarberiaGuard` | Rechazaba al ADMINISTRADOR en POST/PATCH de categorías → 403 en backend, ya correcto. |
| `GET /shops/:shopId/categorias` | Funcionaba para el ADMINISTRADOR (jerarquía), a cualquier sede. |
| `GET .../categorias/:id` | **No existía** el detalle. |
| `app.routes.ts` | `roleGuard(['ADMIN_BARBERIA'])` bloqueaba `/admin/categorias` para el ADMINISTRADOR: el bloqueo real era del **frontend**, no del backend. |
| Mensaje al denegar | Se mostraba el aviso de rol y se redirigía a `/` (pantalla vacía). |

## Test escrito PRIMERO

`src/catalogo/infrastructure/categorias.controller.spec.ts` (rojo antes del cambio):

- ADMINISTRADOR lista categorías de una sede ajena → **200** y evento de auditoría.
- ADMINISTRADOR lee el detalle → **200** y evento de auditoría.
- ADMIN_BARBERIA lee sin generar evento de lectura.
- ADMINISTRADOR en escritura → **403** (`OperadorBarberiaGuard`), ADMIN_BARBERIA/BARBERO → permitido.

Como el detalle no existía, ese caso era rojo por 404/ausencia de ruta; la escritura ya era 403, así que se
fijó como test de no-regresión.

## Cambios

**Backend**

- `categorias.controller.ts`: nuevo `GET /shops/:shopId/categorias/:id` (misma política de lectura que la
  lista); lectura del ADMINISTRADOR auditada (`CATEGORIAS_CONSULTADAS` con `alcance: listado|detalle`,
  `filas` y `origen: ADMINISTRADOR_GLOBAL`, sin datos del catálogo).
- `catalogo.module.ts`: importa `AuditoriaModule` (ya exporta `AuditoriaService`).
- `@Roles` se mantiene en `('ADMIN_BARBERIA','BARBERO')` para lectura: la matriz E1-04/E1-05 concede
  ADMINISTRADOR por jerarquía y `test/permisos-matriz.spec.ts` exige coincidencia exacta decorador↔matriz.

**Frontend**

- `app.routes.ts`: `roleGuard(['ADMIN_BARBERIA','ADMINISTRADOR'])` en `/admin/categorias`.
- `role.guard.ts`: ADMIN_BARBERIA sin acceso vuelve a `/admin/servicios` (antes `/`). BARBERO sigue yendo a
  `/admin/agenda` (H24, sin cambios).
- `admin-categorias.component.ts`: etiqueta visible **«Solo lectura»** para quien no gestiona; sin sede activa
  muestra «Selecciona una sede para ver sus categorías» y **no** llama a la API.
