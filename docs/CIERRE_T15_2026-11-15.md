## 1. ¿Existía ya un endpoint de métricas globales?

**Sí, uno equivalente en parte, y no se reutilizó para el home.** El inventario real:

| Endpoint | Qué devuelve | Por qué no sirve para el home |
|---|---|---|
| `GET /shops/overview` (`BarberiaController` → `AnalyticsService.getShopsOverview`) | Consolidado de un **periodo** con desglose por sede: `totalesGlobales` (ingresos, citas, tasas) + `sedes[]` | Es el contrato del panel de analíticas: recorre sede por sede y agrega reservas y pagos de cada una. Para el home sobra (y falta: no trae cajas ni usuarios) |
| `GET /shops/:shopId/analytics` | Analíticas de UNA sede | Exige `shopId` y `VinculoBarberiaGuard`: es justo lo que el ADMINISTRADOR sin sede no tiene |
| `GET /shops/:shopId/analytics/export` | CSV de una sede | Ídem |

**Creado:** `GET /api/v1/analytics/plataforma/hoy` → `PlataformaAnalyticsController` + `AnalyticsService.metricasPlataformaHoy()`.

- `@Roles('ADMINISTRADOR')` con `JwtAuthGuard` + `RolesGuard`; sin `VinculoBarberiaGuard` porque no hay sede que acotar.
- Cinco contadores en una sola pasada (`Promise.all`): sedes activas, citas de hoy, recaudado hoy, cajas abiertas, usuarios activos. Más `fecha` (etiqueta local del día medido).
- Sin caché a propósito: cinco contadores con índice cuestan menos que un estado del que fiarse para cifras de caja.
- `recaudadoHoy` excluye `estadoPago = 'ANULADO'` y fecha por `registrado_at` (§7.4 / H68), no por la fecha de la cita.
- Rango semiabierto `[hoy 00:00, mañana 00:00)` en local.

## 3. Lógica exacta de `vistaActual()`

```ts
readonly vistaActual = computed<'plataforma' | 'sede'>(() => {
  const rol = this.userRole();                                  // rolEfectivo(roles del token)
  const tieneSede = haySede(this.tenantService.barberiaActivaId());

  if (rol === 'ADMINISTRADOR' && !tieneSede) return 'plataforma';
  return 'sede';
});
```

En la plantilla, el bloque solo se monta para roles de administración:

```html
@if (userRole() === 'ADMINISTRADOR' || userRole() === 'ADMIN_BARBERIA') {
  @if (vistaActual() === 'plataforma') { <app-dashboard-plataforma /> }
  @else { <app-dashboard-sede /> }
}
```

`DashboardSedeComponent` decide a su vez entre estado vacío (sin sede) y tarjetas.

## 6. Qué ve el ADMINISTRADOR sin sede activa

- Cabecera «Métricas de la Plataforma» con la fecha medida y «Red completa · vista de {nombre}».
- Cinco tarjetas: **Sedes activas**, **Citas hoy**, **Recaudado hoy**, **Cajas abiertas**, **Usuarios activos**.
- Un cero se explica: «Sin citas agendadas hoy» / «Sin cobros registrados hoy» en vez de un `$0` mudo.
- Mientras carga: esqueletos, sin cifras. Si falla: tarjeta de error con el mensaje del backend y botón **Reintentar**; nunca ceros.
- CTAs: **Seleccionar sede** (→ `/barberias`), **Ver analíticas consolidadas** (→ `/admin/analytics`), **Gestionar usuarios** (→ `/admin/usuarios`).

Un ADMIN_BARBERIA sin sede ve el estado vacío «Selecciona una sede para comenzar» con el botón **Ver mis sedes**, y no se dispara ninguna petición con `null` en la URL.
